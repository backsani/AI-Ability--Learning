# AI 활용 능력 연습 프로그램

넥토리얼 AI 활용 역량평가 대비용 데스크톱 앱. `넥토리얼 AI활용 역량평가 분석.md`의 분석을 기준으로
실무형 문제를 출제하고, 컴퓨터에 설치된 **에이전트 CLI**(기본값 Claude Code)를 협업 AI로 붙여
실제로 파일을 읽고 쓰고 실행하며 함께 풀게 한 뒤, 학습을 위한 평가지를 남긴다.
**사용자를 채점하는 도구가 아니라 연습 도구**임을 항상 기준으로 삼는다.

## 빌드와 실행

빌드 산출물은 저장소에 포함하지 않으므로 먼저 빌드한다. (.NET 9 SDK 필요)

```
cd NextorialTrainer
dotnet publish -c Release -o ..\app
```

그 다음부터는 `실행.bat` 으로 실행하거나 `app\NextorialTrainer.exe` 를 직접 실행하면 된다.

연습에 쓸 CLI 에이전트는 [설정]에서 고른다(기본값 Claude Code, 유일하게 실제 파일 조작까지
검증됨). 실행 파일은 PATH와 알려진 설치 위치에서 자동으로 찾고, 못 찾으면 경로를 직접
지정한 뒤 [연결 테스트]로 확인하면 된다.

## 화면 흐름

```
홈 → 연습 설정 → 연습(문제 + 채팅 + 작업 폴더) → 평가지 → (같은 조합 재도전 / 지난 연습)
```

- **연습 설정** — 분야를 체크(프리셋 8개 + 직접 추가), 문제 유형(버그 수정 / 스펙 구현 /
  데이터·전략 설계 / 낯선 API 활용) 체크, 난이도 기준, 목표 시간(선택), 협업/평가 모델.
  이번에 낼 분야·유형 조합을 미리 보여주고 [다시 뽑기]로 다시 굴릴 수 있다. 문제의 구체적인
  내용은 연습을 시작해야 생성된다(가벼운 조합 선정과 무거운 문제 생성을 분리).
- **연습** — 문제가 출제되면 협업 AI와 자유롭게 대화하며 푼다. 협업 AI는 세션 전용 작업
  폴더 안에서 실제로 파일을 읽고 쓰고 명령을 실행할 수 있다(파일 목록은 화면 오른쪽에 실시간
  표시). 어떻게 지시하느냐가 이 연습의 핵심이라, 앱은 힌트나 정답을 주지 않는다.
  `Ctrl+Enter`로 전송. 언제든 [제출하고 평가받기]로 종료 가능.
- **평가지** — 총평, **프롬프트 6단계 점검**(문제 재정의/계획/학습/작은 단위 요청/검증/마무리),
  **5개 평가 항목**(문제 정의/새 기술 습득/결과물 검증/커뮤니케이션/기본기), 막연하게 위임한
  표현·잘 쓴 프롬프트 인용, 결과물 검토, **이 문제가 실제로 확인하려던 것**(세션 중엔 숨겨졌던
  채점 기준 공개), 다음에 시도해볼 것, 대화 전문. 점수·등급은 없다 — 평가가 아니라 학습이 목적.
- **지난 연습** — 저장된 평가지 목록/검색/열람/삭제.
- **학습 현황** — 분야 × 문제 유형 조합별로 몇 번 풀어봤는지, 최근에 몇 개 항목에서 "충분"을
  받았는지 확인한다.

## 문제 조합 선정 — 매번 같은 문제가 나오지 않게

연습 한 번은 CLI 세션 하나라, 시작 시점의 모델은 이전 연습을 전혀 모른다. 그래서
**(분야, 문제 유형) 조합은 앱이 정한다** (`ProblemPlanner`, 안 풀어본 조합 > 최근 부진했던
조합 > 오래된 조합 순, 소량의 난수 포함 — 면접 프로그램의 `TopicPlanner`와 같은 원리).
같은 조합을 다시 낼 때는 지난 문제 제목을 모아 "이건 피하라"고 출제 프롬프트에 넣는다.

## AI의 세 가지 역할

한 번의 연습에 AI가 세 번 다른 역할로 호출된다. 전부 [설정]의 CLI를 그대로 쓰지만, 인자와
권한이 다르다.

| 역할 | 언제 | 도구 | 목적 |
|---|---|---|---|
| 출제자 | 연습 시작 시 1회 | 없음 | 문제·시작 파일·채점자 전용 확인 기준 생성 |
| 협업 AI | 대화 내내 | **있음** (세션 작업 폴더에 한정) | 사용자와 함께 실제로 문제를 품 |
| 평가자 | 제출 시 1회 | 없음 | 전체 대화 + 작업 폴더 상태로 학습용 평가지 작성 |

출제자·평가자는 `EvalModel`, 협업 AI는 `CollabModel`을 쓴다. 저렴한 모델로 협업하고
평가만 강한 모델로 올리는 식으로 설정하면 된다.

### 협업 AI가 실제로 파일을 만지는 방식 (실측 확인됨)

Claude Code CLI로 직접 검증한 내용:

- `--permission-mode bypassPermissions`를 주면 `-p`(비대화형) 모드에서도 권한 프롬프트 없이
  파일 읽기/쓰기/명령 실행이 그대로 된다. 작업 디렉터리(`WorkingDirectory`)를 세션 전용
  폴더로 고정하면 파일 도구가 그 폴더에 한정된다(Bash 도구 자체는 한정되지 않으므로, 이는
  사용자가 자기 컴퓨터에서 Claude Code를 직접 쓰는 것과 같은 신뢰 수준이다).
- `--system-prompt-snapshot on`을 첫 턴에 주면, 이후 `--resume` 턴에서 `--system-prompt`를
  다시 보내지 않아도 페르소나가 유지된다(면접 프로그램이 쓰던 "매 턴 재전송" 방식보다 간단).
- 문제 출제·평가는 `--tools ""`로 도구를 꺼서 부작용 없이 빠르게 끝낸다.

다른 CLI 프리셋(Codex/Gemini/Cursor/opencode)은 협업 시 실제 파일 조작이 검증되지 않았다.
[설정] → [고급]의 "협업(파일 조작) 첫 턴 인자"가 비어 있으면 문제 출제용 인자로 대체되는데,
이 경우 협업 AI가 도구 없이 채팅만 하게 된다.

## 저장 위치

```
%APPDATA%\NextorialTrainer\
  settings.json     설정 (선택한 CLI, CLI별 경로·모델·인자, 테마, 직접 추가한 분야)
  reports\          평가지 (.json, 마크다운 내보내기 시 .md)
  workspaces\<id>\  세션별 작업 폴더 — 협업 AI가 실제로 읽고 쓴 파일이 그대로 남는다
  cli-workdir\      출제·평가용 CLI 작업 폴더 (비어 있음)
```

평가지 JSON에는 대화 전문과 작업 폴더 경로까지 들어 있어서, 나중에 앱에서 그대로 다시 열어보거나
작업 폴더를 탐색기로 열어볼 수 있다.

## 구조

```
NextorialTrainer/
  Common/       ObservableObject, RelayCommand, JsonBlock(응답에서 JSON 추출), Utf8
  Models/       AppSettings, PracticeConfig, ChatMessage, ProblemBrief, PracticeReport,
                ProblemType(4유형 카탈로그), DomainTypeStatus, CliAgentProfile
  Services/
    DomainCatalog        분야 프리셋
    PracticeHistoryProfile  평가지 전체 → (분야,유형) 조합별 이력 집계
    ProblemPlanner       이번 연습의 분야·유형 조합 선정
    CliAgentCatalog      내장 CLI 프리셋 (출제·평가용 / 협업용 인자 둘 다 서술)
    CliAgentBackend      프로파일대로 아무 CLI나 구동 + 대화 상태 관리 (역할별 워크디렉터리)
    ArgTemplate          인자 템플릿 → 실제 인자 목록
    WorkspaceManager     세션별 작업 폴더 생성·파일 목록·평가용 스냅샷 텍스트
    PracticeSession      한 번의 연습 (문제 생성 → 협업 대화 → 평가), 어떤 CLI인지 모름
    PromptBuilder        출제/협업/평가 프롬프트
    ReportStore, MarkdownExporter, SettingsService, AppPaths
  ViewModels/   Main, Home, Setup, Practice, Result, History, Progress, Settings
  Views/        위 VM에 1:1 대응하는 axaml + MarkdownView(코드 전용 경량 마크다운 렌더러)
```

CLI 연동 방식(세션 방식 Resume/Replay, 인자 템플릿 문법, 미검증 프리셋 처리 등)은
`Ai 면접 프로그램`과 동일한 설계를 그대로 따른다.

## 기술 스택

net9.0 / Avalonia 11.2.3 / 외부 MVVM 프레임워크 없음.
